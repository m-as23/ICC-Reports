# MainTrack security regression

Run `python security-regression/run.py --mode local` from the existing repository/workspace. This performs bounded local checks and emits one JSON report. Identical component inputs, test definitions and evidence are reused without rerunning; an APK change invalidates artifact-bound evidence. `--changed path` may be supplied repeatedly. Unknown code paths invalidate every case; documentation-only changes do not launch Android. The catalog is conservative and must be reviewed when source paths move.

`--mode release --artifact path/to/candidate.apk` is a fail-closed release gate: missing required evidence is NOT TESTED and returns a nonzero exit code. A green local check is not distribution approval. Runtime cases default to NOT TESTED. A local runtime-evidence.json may import reviewed PASS or FAIL results only when APK, input, test-definition and evidence hashes match; do not edit their status to manufacture GO. The offline finalize_evidence.py adapter indexes this run without repeating any Android or cloud request.

Safety primitives enforce request counts, an absolute deadline, pacing after responses, a persistent intent journal and bounded subprocess time/output. An unresolved write is AMBIGUOUS across restart and cannot be retried automatically. Test helpers never open the cloud gate on their own. The separate approved-window lab uses memory-only fresh synthetic passwords/capabilities; its public handles contain hashes, never passwords or bearer tokens. The cloud gate is the authoritative shared counter across native/background/direct requests.

Local TLS/OTA fixtures are inert, use throwaway keys and loopback-only HTTPS. The test CA is scoped to `10.0.2.2` in the QA APK. Neither Windows nor a device-wide trust store is modified. The native updater has auto-update off, empty telemetry URL, immutable local update/channel URLs and a download override restricted to three fixture ZIP paths. This instrumented development configuration cannot certify the operational APK's default transport or updater settings.

No scheduler or resident runner is installed. Cloud execution requires a fresh explicit bounded authorization; release-time Android uses the existing Windows SDK/AVD. Do not put cloud secrets in Actions, run Android/QA on untrusted pull requests, or configure a self-hosted runner to execute untrusted PR code. The workflow has read-only permissions and a five-minute deadline; its PostgreSQL 17 fixture is disposable, loopback-published, limited to 256 MB/one CPU and contains generated data only. It never connects to Supabase. Activation as a required branch/release check needs repository-owner policy; a draft PR alone cannot enforce distribution.

Cleanup is a separate mandatory proof. An expired capability is not verified restoration. The gate requires server-clock timestamps, timely verified baseline/session closure, preserved archives, demonstrated scheduler execution and a controller-failure exercise, all bound to the candidate source/APK and hashed evidence. Missing XLSX-new-item or Android TLS-rejection evidence also blocks GO. A 130-minute cleanup overrun remains FAIL even after eventual restoration.

`ops/maintrack/security/qa-cleanup-lease.sql` is a QA-only **review design**, never deployed by CI. Its private lease has a worker heartbeat before admission, deadline-bound synthetic sessions, Inventory-only write guards, durable recovery attempts, verified pointer/items/version restoration and retained audit/archives. `CALL sweep(...)` must be a top-level call by the private worker member; a preceding SET in the same query string prevents transaction control. Already executing transactions may commit after admission closes; recovery takes table locks to drain them before verification. Scheduler delivery, connection timeout, final job closure and Storage orphan cleanup still require separate proof. Local SQL PASS does not establish operational cleanup reliability. Cloud XLSX stays closed until these prerequisites are resolved.

`python security-regression/cleanup_postgres.py` runs only against an explicitly marked, newly created loopback fixture (see tests). Without one it exits 78/BLOCKED, never passes skipped SQL tests. No installed PostgreSQL database is reset. Its fixture-owned schemas/roles may be reset only after the database ownership marker is verified. No credential columns or real data are used.

Historical evidence remains under `evidence/online` and is indexed separately with hashes. The old 54/80 value is admitted HTTP requests, not passed/failed tests. Previously passed tests are not relabeled as fresh executions. Scope, identity, APK hash and parity limits accompany each result.

This package adds no production deployment, signing material, backend, paid service or merge authorization. PR #25 remains separately reviewed and unmerged. Preserve append-only audit evidence; clean only exact run-tagged fixtures and restore original QA data using server-side rollback material, never export original password hashes.
