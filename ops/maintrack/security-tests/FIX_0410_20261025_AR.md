25 أكتوبر 2026، بتوقيت القاهرة. التنفيذ على الفرع المعزول `audit/maintrack-0410-security-performance-20261025`، دون تعديل main أو نشر Web/APK جديد.

مصدر الإصلاح: `e856ec053a56eb66757b7d48ce9dbdfab4b57e98`.

## التغيير والنتيجة

- **A-01 مغلقة ضمن نطاقها:** التحقق من كود الموظف يسبق تحديث حصة الدخول المشتركة. الاختبار يعيد 301 طلب بكود غير صالح، ثم ينجح دخول حساب صناعي صالح، وتبقى الحصة محتسبة لمحاولة واحدة فقط. الاختبارات تثبت أيضًا استمرار الحد العام عند 300 محاولة صالحة الشكل خلال خمس دقائق، واستمرار قفل الحساب بعد خمس كلمات مرور خاطئة. هذا لا يدعي حل هجمات الإغراق الموزعة بأكواد صالحة الشكل؛ ضوابط الحافة مسار مستقل.
- **A-02 مغلقة:** قراءة متدفقة محدودة إلى 65,536 بايت فعليًا، ورفض الزيادة بـ413 وإلغاء القارئ. الاختبارات تغطي غياب Content-Length أو تقليله، تعدد الأجزاء، العربية وحجم UTF-8، قبول الحد نفسه ورفض بايت إضافي.
- **A-03 مغلقة:** JSON غير الصالح يعاد له 400 INVALID_PAYLOAD، وتظل أخطاء السيرفر غير المتوقعة 500 دون كشف تفاصيلها.

التغيير الإنتاجي محصور في index.ts: قارئ JSON المحدود وترتيب التحقق من الكود. لم تتغير كلمات المرور أو قواعد الصلاحيات أو SQL كتابة البلاغات/الطلبات أو الجداول. ledger-service.mjs وdeno.json كما كانا بايتًا ببايت.

## أدلة التحقق

- قبل الإصلاح: الاختبارات الثلاثة الأصلية فشلت للسبب المتوقع. بعد توسيع حالات الحدود: ست حالات فاشلة، ثم أصبحت خضراء بعد الإصلاح.
- محليًا: 58/58 لاختبارات API والأمان وسياسة كلمات المرور، 18/18 للأرصدة، 88/88 لخدمات المخزن و20/20 لكاشه.
- التشغيل الكامل npm test لحزمة Native: 114 اختبارًا؛ 113 نجاحًا وفشل تاريخي واحد: `Stage22 source changes exactly the three approved UI resources, never other locked assets` في shared-source.test.mjs. يثبت هذا الاختبار مصدر 0.4.6 التاريخي؛ لم يُغيّر تثبيته ولم يُعرض التشغيل الكامل كنجاح. ضمن الـ113 الناجحة توجد اختبارات التشغيل الحالية وحارس آخر تاريخي ناجح.
- [تشغيل GitHub 40150588893](https://github.com/m-as23/ICC-Reports/actions/runs/40150588893): **47/47** لاختبارات معالج Final المرشح و**20/20** لاختبارات المتصفح والبطء والكاش وحماية التفعيل. كلا Job ناجح. المتصفح يختبر مصدر الواجهة الثابت للتحديث 0.4.10؛ لم يتغير في هذا الإصلاح.

## النشر والفحص الحي

`maintrack-final-047` على MainTrack-Staging أصبح **v3 ACTIVE**. أُعيد تحميل الملفات المنشورة والتأكد من تطابق index.ts مع المصدر الذي اجتاز CI، ومن عدم تغير الملفين التابعين. حافظنا على verify_jwt=false القائم لأن التطبيق يتحقق من جلساته opaque داخل الخدمة؛ لم نغير طريقة المصادقة.

سبعة طلبات خفيفة بعد النشر: health 200، ready 200، JSON مقطوع 400 INVALID_PAYLOAD، جسم زائد 413 PAYLOAD_TOO_LARGE، كود غير صالح 400 INVALID_CODE، غياب جلسة 401 AUTH، مصدر غير مسموح 403 ORIGIN_FORBIDDEN. لم تُرسل محاولات إغراق أو كلمات مرور حسابات حقيقية. اختبار غياب هيدر الحجم/تقليله جرى محليًا، لأن عميل الفحص الحي قد يضيف Content-Length تلقائيًا.

لا يلزم APK أو OTA جديد؛ APK الأساسي 0.4.7 والتحديث الداخلي 0.4.10 يستفيدان من الـAPI نفسه. لم تُنفذ ترقية مكتبات أو تغيير قاعدة بيانات، ولم تُعدّل سجلات المستخدمين أو البلاغات أو الإجازات أو الإضافي أو المخزن.

## المتبقي خارج هذا الإصلاح

تنبيهات اعتماديات استيراد Excel، وتجهيز مراقبة ميدانية مستمرة، ونسخة احتياطية حديثة واختبار استرجاعها ما زالت مفتوحة. Workflow الاختبار يعمل على فرع audit عند تغيير المصدر أو الاختبارات؛ لم يدمج في بوابة فرع الإصدار أو main بعد. بوابة الفرع المعزول تحقق عيوب التطبيق المعروفة، وليست ضمانًا كاملًا ضد الاختراق أو DDoS.
